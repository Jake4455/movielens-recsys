## 本轮修复（2026-10-08）

### P0：负采样非均匀（已修复 + 全臂重跑 44.7 分钟）

`src/data/candidates.py::_sample_negatives` 原先抽 256 个 code，用 `np.unique` 去重（**升序**），再 `collected[:100]` 截断 —— 实际保留的是**最小的 100 个** code，是顺序统计量而非均匀抽样；同一函数还被 `src/rank/build_training.py` 复用，训练负样本同样有偏。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 目录中被用作负样本的位次 | 42,823 / 87,585（48.9%） | **87,585（100%）** |
| 负样本位次中位数 | 17,276 | 43,865（均匀期望 43,792） |
| 负样本平均训练期评分数 | 647.75（目录均值 294.24） | 264.64 |
| R00 热门基线 NDCG@10 | 0.615445 | **0.754027** |
| R10 lift | 1.2356（+23.56%） | **1.1388（+13.88%）** |

修复：`collected = rng.permutation(collected)[:n_negatives]`（均匀样本的均匀子样本仍均匀），并补了说明性 docstring。

> 方向说明：偏热的负样本让正样本更难排到前列，因此**压低了基线**（0.6154 < 0.7540），从而**夸大了 lift**。修复后达标判据仍满足（1.1388 ≥ 1.1 且 CI 下界 > 0），但余量由 +0.136 收窄到 +0.039。

### P1（已修复，已随本轮重跑生效）

1. **训练/验证组的负样本排除范围**：`src/stages.py` 由 `train`（验证为 `train+val`）扩到 **`train+val+test`**，与测试候选规则一致，消除"训练负样本即评测正样本"的矛盾标签。
2. **`data.candidates.source` / `teacher_file` 通道**：原先只写进 meta、没有任何代码读取，会在 `source: teacher` 时记录虚假来源。现改为 `source != local` 直接 `NotImplementedError`（Q7 确认格式后再实现加载与校验）。
3. **组大小断言**：`src/eval/ndcg.py::evaluate_candidates` 新增 `expected_group_size`，在基线、LTR 验证、LTR 测试、σ_seed 四处调用点强制"每用户 1 正 + K 负"。
4. **延迟/吞吐口径**：`src/eval/run_ranking.py` 新增 `infer_s`。
   - `outputs/leaderboard.csv` 的 `latency_ms` / `throughput_rps` = **管线代理值**（阶段总耗时 / 用户数），另存 `pipeline_s`；
   - `outputs/top10/<run>_meta.json` 新增 `latency_ms` / `throughput_rps` / `latency_scope: inference_only` = **纯推理口径**（R10：0.1206 ms/用户、837,176 行/秒）。
   - 显著性检验新增用户集一致性断言（模型与基线的用户集必须完全相同）。
5. **顺带修复**：ALS 因子缺失改为 fail-fast（原先静默把 `als_score` 置 0）；`basic.py` 自排除键的 `-1` 电影码别名冲突；`distributed.py` 阈值改为从配置传入；`seeds.py` 的 `PYTHONHASHSEED` 说明更正（该变量只能在解释器启动前生效，此处实际只影响子进程）；`run_all.py` 空 `--stages` 报错、启动时记录 stages/force。

### P0（交付层）：`.gitignore` 把 `src/data/` 整个包忽略了

`.gitignore` 第 1 行原为 `data/`（无前导斜杠），在 gitignore 语法中会匹配**任意层级**名为 `data` 的目录，因此 `src/data/`（`__init__.py`/`schema.py`/`io.py`/`split.py`/`candidates.py`/`validate.py`/`stats.py` 共 7 个文件）**从未进入版本库**。后果：任何 clone 该仓库的人执行 `run_all.py` 都会在第一行 import 处失败（`from src.data import schema`），直接违反任务书「完整源代码…教师可用提交的代码重新运行」。

- 修复：`.gitignore` 改为 `/data/`（仅忽略仓库根目录的原始数据），并加注释说明原因。
- 影响面：仓库跟踪文件由 90 → 97（+7 个源码文件）；根 `data/` 仍被忽略（原始数据不提交的合规要求不变）。
- 验证：`git check-ignore -v src/data/candidates.py` 不再命中；`git status` 中 `src/data/` 变为待提交的新文件。
