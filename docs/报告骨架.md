## 0. 摘要（TODO）

一句话模板：在 MovieLens 32M 上构建"Spark 分布式 + 流式增量 + 图特征 + 学习排序 + ItemCF 召回特征"的推荐系统，在教师协议（每用户 1 正 + 100 固定负）下，Top-10 NDCG@10 从热门基线 **0.7540** 提升至 **0.8728（+15.75%）**，配对 95% CI 下界 **+0.1177**，σ_seed = **0.000363**（5/5 套 ≥ 1.1，最小 lift 1.1561）；系统侧 ALS 全流程 352s、单用户推理延迟 0.250ms（管线代理 3.33ms）、扩展性加速比 1.97（local[8]）。

## 1. 问题定义

- 数据：MovieLens 32M（32,000,204 评分 / 2,000,072 标签 / 200,948 用户 / 87,585 电影，1995-01 至 2023-10）；校验见 `outputs/reports/data_quality.md`（重复 0、缺失 0、覆盖率 100%）。
- 协议（教师统一规定）：
  - 正反馈：`rating >= 4`；
  - 每用户按时间戳 80/10/10 划分（train 25,771,222 / val 3,114,491 / test 3,114,491）；
  - 测试候选集：1 正 + 100 固定负，种子 `20260907`（本地按"均匀随机 + 排除已交互"复现）；
  - 防泄漏：特征只能使用推荐时刻 t 之前的数据。
- 指标：NDCG@10（每条用户 1 个正样本，故 IDCG=1，NDCG = 1/log2(rank+1) 若 rank≤10），同时记录 Recall@10（=HR@10）、吞吐、延迟。NDCG 位置表：rank1=1.0，rank10=0.289。
- 目标：`lift ≥ 1.1` 且用户配对 95% CI 下界 > 0，且 σ_seed 稳健（§4.6）。

## 2. 算法设计

**主线：Learning-to-Rank 重排序**（本协议下召回不决定指标，增益集中在排序层）。

| 模块 | 算法 | 角色 |
|---|---|---|
| 主排序器 | LightGBM LambdaRank（`lambdarank_truncation_level=10`，300 轮，early stopping 50） | 唯一直接决定 NDCG |
| 协同特征 F1 | Spark MLlib ALS（rank=64, iter=10, nonnegative）+ 热度/活跃度统计 | ALS 直接排序仅 0.279，作为特征后贡献显著 |
| 内容特征 F2 | genre 多热、tag 画像、贝叶斯平滑评分、年份差 | 补充长尾区分度（移植特征边际 −0.000284） |
| 时序特征 F3 | Structured Streaming 日窗聚合 + 时间衰减；**比值型**近 7/30 天热度、用户 7/30/90 活跃比 | 最大单项增益（+0.0373），gain 第 1 |
| 图特征 F4 | 用户-电影二部图 PageRank（阻尼 0.85/20 轮）+ Louvain 社区 + 截断随机游走 | PageRank 有效（+0.0011）；后两者负结果 |
| 召回（任务二） | ItemCF 精确余弦 Top-K + SimHash（随机投影 + banding） | 准确率—效率证据，不进 NDCG |
| 难负样本 | easy(均匀) : hard(热门未交互) 混合 | 负结果（分布错配） |
| 训练样本 | 每用户 leave-one-out：1 正 + 100 负 = 101 行/组，与测试同构 | val 亦用同协议早停 |

## 3. 系统架构

```
数据层   raw → cleaned → train/val/test → 1+100 候选（seed 20260907）
算法层   F1 协同(Spark ALS/ItemCF) · F2 内容 · F3 流式(Structured Streaming) · F4 图(PageRank/Louvain)
         └──► LightGBM LambdaRank ──► Top-10
服务层   outputs/top10/*.csv + 生成时间 + 模型版本 + 吞吐/延迟
实验层   conf/*.yaml + outputs/leaderboard.csv + outputs/reports/* + 配对检验 + σ_seed
```

- 目录骨架与运行命令见 `docs/阶段性总结.md` §2/§3；一键复现：`python run_all.py --config conf/final.yaml`。
- 分布式边界：Spark 负责 ALS 训练/打分、流式窗口聚合、统计特征；图/相似度为单机 scipy/igraph（含原因说明，见 `docs/阶段性总结.md` §6.5）。

## 4. 实验设置

- 环境：Windows、Python 3.11（conda `mlrecsys`）、PySpark 4.0.0、LightGBM 4.7.0、pandas 2.2.3、numpy 1.26.4、JDK 21；Spark `local[8]`、driver 8g。
- 随机性：全局种子 20260907；LightGBM `deterministic=true, force_row_wise=true`；重跑逐位一致（NFR-1 已复验）。
- 统计口径：用户配对 bootstrap（B=1000）报告 Δ、SE、95% CI、单侧 p；候选集种子稳健性 σ_seed（官方 + 4 套重采样）。
- 消融维度：10 → 12 → 13 → 16 特征；难负样本 0 vs 0.2；图模块 on/off；F3 绝对 vs 比值口径；SimHash 9 组参数；ALS 并行度 2/4/6/8。

## 5. 结果分析

- 主表：见 `docs/消融总表.md`（R00/R03/R06/R07/R08/R10/R09/R11/R12/R13 共 10 行）。

| 结论 | 证据 |
|---|---|
| 达标：+15.75% | R13 test NDCG 0.8728，基线 0.7540，CI 下界 +0.1177，p<0.001 |
| 最大增益来自 F3 时序比值 | 13→16 特征 +0.0373；`movie_recent_ratio_7_30` gain 第 1（1085 分裂） |
| 召回特征有效（任务六"组合召回"） | 16→17（含训练设置）：+0.0141；`itemcf_max_sim` gain 第 2（1.95e6、1622 分裂） |
| PageRank 为正 | 12→13 特征 +0.0011 |
| 反向发现 1：两种难负样本均无效 | 0.8518（流行）/ 0.8224（真实负反馈，best_iter=4）< R10 的 0.8587 |
| 反向发现 2：绝对时间特征退化 | best_iter=1，`movie_recent_30d` 8 分裂吃 95 万 gain |
| 反向发现 3：walk/社区特征负 | 训练期自身边/NaN 不对称，已修复或关闭 |
| 反向发现 4：LSH 无净收益 | 高召回要扫 67–99% 物品；低候选 recall@50 <0.4 |
| 反向发现 5：候选集"形状合规≠分布合规" | 负采样在 `np.unique` 排序后截断，51% 目录不可达；修复后基线 0.6154→0.7540 |
| 反向发现 6：早停会被并列分数误判 | 同特征开/关早停：0.8296 vs 0.8728（差 0.043）；内部指标按行序破并列而正样本在每组首行 |

- 机制解释：增益来自"101 选 10"的位置提升（rank 2–10 → rank 1，R13 的 rank-1 占比 73.30% vs 基线 53.07%）；热度先验（movie_count + PageRank）与个性化信号（ALS、趋势比、召回相似度）互补。

## 6. 局限性

1. **协议口径未确认（Q1/Q6/Q7）**：候选负样本采样规则直接决定基线强度（本地均匀抽样下 0.7540；若教师采用更聪明的负采样，基线会下降，+10% 难度随之变化）。
2. 时间漂移：训练/测试按时序切分，任何与绝对时间强相关的特征都会退化（F3 绝对值、walk 均被证实）；比值化只能缓解。
3. 单机资源：Spark `local[8]` 为伪分布式，扩展性加速比 1.97 受 4P+8E 混合核限制；真实集群结论可能不同。
4. 未使用深度排序（LightGCN/SASRec 仅列为对照臂，显存不足未做）。
5. ~~召回特征与"关闭早停"两项改动未拆分~~ ✅ **已闭环（2026-10-09）**：R14 = R10 + 固定 300 轮 → 0.858790；拆分结果：召回特征 **+0.013996（99.1%，CI [+0.013355, +0.014598]）**、训练轮数 +0.000130（噪声）。
6. 冷启动策略简单（特征 NaN/0，靠树模型内建处理），未做专门建模。
