## 3. 表注（负结果与口径说明）

1. **两种难负样本均无效**（同一 16 特征管线下的三臂对照）：R10（hard_ratio=0）0.7604 > R09（流行难负）0.7585 > R11（真实负反馈）0.7362。流行难负把冷门均匀负样本替换为热门项，造成冷热错配；真实负反馈（用户 rating<4 的已交互项）更差，因为它替换掉 20 个均匀负样本，而测试候选**完全排除已交互项**，这份"已看但不喜欢"的信号无法迁移到测试分布，反而让训练分布偏离测试分布。结论：本协议下保留 `hard_ratio=0`。另修复采样缺陷：easy 与 hard 回退路径独立采样可能产生重复（dev 冒烟发现 3 处），已改为"先采 hard 并临时屏蔽、再采 easy"，R09/R11 均为修复后重跑。
2. **图特征 `graph_walk2` 与 `graph_community_affinity` 无效**（未进入 R08）：walk 在训练期被用户自身共现边抬高（正样本均值 1.29 vs 验证 0.68），4 次分裂吃 107 万 gain；Louvain 社区特征数值近乎恒 0 却异常主导（36 次分裂 733 万 gain）。两者已关闭，仅保留 PageRank。（注：walk/community 数值为 2026-09-16 修复前口径，2026-09-18 修复图 topk 自身相似度错位后未重跑；PageRank 不受影响。）
3. **F3 绝对值口径退化**：近 7/30/90 天绝对计数把"年代整体活跃度"编码进来，训练/测试时间尺度漂移导致 best_iter=1；改为比值型后泛化。
4. **R01/R02（召回）不进入 leaderboard**：本协议下召回率不决定 NDCG，ItemCF 与 SimHash 以"准确率—效率"报告为证据（`outputs/reports/recall_lsh.md`），结论为本规模下 LSH 无净收益。
5. **延迟口径**：`延迟 (ms)` = 该 run 阶段总耗时 / 测试用户数（含特征生成与批量推理的管线代理值），非在线单请求服务延迟；服务层延迟以 Top-10 输出元数据为准。
6. **R09/R11 为 16 特征版且同种子**，与 R10 仅差 `hard_ratio` 与 hard 源，可直接对比；R09 的旧 10 特征结果（0.7000）已被本轮重跑取代。
